# 建筑风格学习与原创生成工作流 v1

这套流程解决的不是“把 PAR-001 再修一次”，而是让生成系统先学习现实建筑的组织方法和玩家的方块表达手法，再创造新的建筑。旧的 `design.py` 与 `paris_style_v0.1.json` 把风格、构件和单栋坐标混在一起，只能稳定复制一种答案；从本流程开始，PAR-001 视为旧实例，不再作为风格定义。

## 一、四层知识必须分离

1. **现实建筑原型层**：记录街道、地块、体量、立面层级、开间、屋顶、材料角色及历史条件。这里不出现 Minecraft 方块名和单栋坐标。
2. **Minecraft 构件手法层**：记录一个窗、檐口、栏杆、墙缝或屋顶转角如何由准确方块状态、深度层、遮挡和观察角度构成。这里不把一个构件上升为整栋风格。
3. **建筑框架层**：记录新建筑的地块、轮廓、各面角色、层级、开间、洞口、入口轴、阳台大线和屋顶。这里禁止窗套、栏杆、调试棒造型和材料斑点。
4. **实例层**：保存种子、选择路径、完整坐标、构件装配结果和 `.schem`。实例只消费前三层知识，不反向污染风格规则；只有跨多个作品验证过的结论才能晋升为规则。

对应的首个分离式风格模型是 `knowledge/styles/paris_haussmann_v0.1.json`。旧 `grammar/paris_style_v0.1.json`（已随 PAR-001 归档到 `archive/PAR-001/grammar/`）中的 `first_original_run` 正是错误耦合的例子，保留它仅用于追溯。

## 二、固定生产流程与硬门槛

### G0：设计任务书

先明确城市/时期、建筑用途、地块关系、临街方向、尺度预算、主要观察距离和必须工作的观察角度。若只给“法国风格”，系统必须先把范围收窄为可研究的建筑类型，不能直接选方块。

产物：`brief.json`。字段至少包括目标风格、用途、地块、尺度、主要视角、客户端版本和禁止事项。

### G1：外部建筑研究

每个新风格至少使用三份权威来源，优先城市规划机构、博物馆、档案、测绘或学术资料。网页图片用于识别构图关系，文字和测绘用于确认事实。每条结论分为：

- **观察事实**：来源明确写出或图纸直接显示；
- **设计推论**：我们为 Minecraft 转译而做的判断；
- **可变范围**：同一风格允许变化的部分；
- **反例/边界**：什么相似外观不属于该规则。

本轮巴黎试点采用 Ville de Paris、Pavillon de l'Arsenal 和 APUR 的资料。得到的关键关系是街宽与高度、连续街墙、基座—主体—檐口—屋顶、选定楼层阳台、规则网格中的装饰变化，以及街面、院面、屋顶和烟囱作为同一系统。来源与逐条证据已写入风格模型。

通过条件：每个不可变规则都有来源；现实事实与 Minecraft 译法分开；文件中不存在 PAR-001 的 run、路径或坐标。

### G2：内部优秀作品的构件拆解

先批量提取事实，再做语义标注，不能只看截图凭印象总结。

自动提取每个 `.schem` 的：

- 尺寸、完整 palette、每个准确 block state 和数量；
- 正面/侧面/顶面的投影占用、深度和轮廓哈希；
- 孤立方块候选；
- 墙、楼梯、玻璃板、栅栏门、活板门等带状态构件；
- 可能受邻接更新影响的状态候选。

然后按屋顶、窗、门、墙面、檐口、阳台、店面、转角、烟囱等裁成构件。每个构件必须填写 `knowledge/component_annotation.schema.json` 所列字段，尤其是：语义作用、源坐标、室外朝向、有效观察锥、前后深度层、遮挡关系、支撑关系、尺度范围和更新策略。

“带状态”不等于“必须禁止更新”。判定调试棒/禁止更新手法必须做游戏内 A/B：

1. 同一构件分别以正常更新和禁止邻接更新粘贴；
2. 截取粘贴后、一次相邻方块变化后、区块重载后的状态；
3. 比较 NBT 状态和正面、45°、侧面外观；
4. 只有正常路径改变造型而禁止更新路径保存造型时，标记 `needs_suppressed_updates`；
5. 若区块重载后失效，记录为不可交付手法，不能仅靠预览器通过。

文件阶段通过条件：构件有坐标级证据和完整状态；至少完成规定视角；构件可以脱离原建筑复现。游戏 A/B 集中在最后双包阶段进行，在此之前更新策略必须保持待测；不得把文件阶段通过写成生产稳定。

### G3：形成“风格方法”，不形成模板

把 G1 的建筑关系与 G2 的玩家手法连接成条件规则：例如“贵族层需要更强水平层级”是建筑目标，“整层阳台板 + 某类细栏杆构件”是一个可选实现。一个目标必须允许多个兼容构件或允许暂时无构件，不能绑定唯一坐标模板。

风格模型只含：不可变量、范围、条件规则、可选母题、反模式和证据。材质只按角色描述；具体方块方案属于构件库。

### G4：重新生成五套框架

随机性必须作用于有建筑意义的选择：地块/院落、宽深比、开间数、入口轴、转角、中央凸退、层数、阳台层级、屋顶轮廓。使用分离种子：`massing_seed`、`facade_seed`、`detail_seed`，保存完整选择路径。相同种子必须完全复现；不同种子至少改变三个建筑轴，且轮廓或多面关系可感知不同。

框架可以包含洞口、楼层关系、入口、整层阳台板和屋顶，因为这些决定建筑构图；禁止窗套、栏杆、墙状态雕花、材质噪声和小道具。系统不得在这一步“把空白墙补漂亮”。

### G5：多面与多视图框架验收

每个候选固定输出 front、back、left、right、top、axonometric_front、axonometric_back 七图。对每一个面说明：它是主街面、院面、转角回折还是邻接山墙；45°视角说明两个面如何交接。以下任一情况直接退回 G4：

- 只正面成立，侧面是被拉长的重复或空白；
- 正视有节奏，45°时洞口、凸退或屋顶互相打架；
- 顶视无法解释院落、退台、屋脊和烟囱位置；
- 去掉细节后无法读出基座、主体、重点层和屋顶；
- 参数不同但画面仍是同一轮廓。

框架评分只评五项：城市/地块关系 20、多面闭合 20、轮廓与比例 20、立面层级 20、360°可读性 20。任何单项低于 14 或总分低于 80 均不进入细节阶段。七图之外另渲染两种高度、每45°一张的16张环视图。分数必须附具体视图依据，不能自报分数代替评审。

选定框架后生成三套一级立面构图，比较入口位置、开间宽度组合、连续或分组阳台、店面节奏及屋顶开窗。保存 framework_review.json 和 facade_review.json；命令行在缺少评审或种子不一致时阻止进入后续阶段。

### G6：构件语法装配

选定框架后，按建筑层级装配构件：先入口、主阳台、檐口、屋顶中断等一级构件；再普通窗、墙面分缝等二级构件；最后五金、花箱等三级构件。每个构件在放置前检查方向、尺度、深度预算、遮挡、相邻状态和观察锥。调试棒手法只放在它能表达明确建筑作用的位置，不能成为全墙纹理。

同一建筑至少使用两种兼容的窗/开间变体，但变体服从共同轴网。随机选择必须受“楼层、面、重点区”条件控制，禁止逐方块随机。

### G7：技术验证与双重视觉对照

继续执行现有 Sponge 回读、独立 JS 注册表、几何、冻结状态回读和七视图渲染。视觉对照分成两组：

- 与外部建筑证据比较体量、层级和风格关系；
- 与内部优秀素材比较方块尺度、状态手法、深度和精细度。

二者不能互相替代。像现实巴黎但不像用户的 Minecraft 手法，或方块很精巧但建筑关系错误，都必须退回相应阶段。

### G8：游戏内验证与知识回写

用户在目标版本游戏内粘贴验收。失败项回写到“实例诊断”，不能直接改写风格。只有同一结论在多个来源、多个新实例和游戏内结果中重复成立，才可从推论晋升为规则。保留被拒候选和原因，避免下一轮再次随机到同一失败模式。

## 三、本轮可行性试验

运行：

```bash
cd paris-builder
source .venv/bin/activate
PYTHONPATH=src python -m unittest -v tests/test_learning_workflow.py
PYTHONPATH=src python tools/run_style_learning_pilot.py \
  --output runs/STYLE-LEARNING-PILOT-v0.1
```

试验实际完成了：

- 扫描 43 个窗构件和 14 个建筑源文件，保留完整状态与多视图投影证据；
- 将“疑似依赖更新抑制”明确标成待游戏内 A/B，不伪装成已证实结论；
- 从独立风格模型用三个种子生成三套不同框架；
- 框架只含层级、开间洞口、入口、阳台大线、各面关系和屋顶；
- 三个 `.schem` 全部回读 PASS，并各自输出七视图；
- 单元验证证明同种子可复现、不同种子改变至少三个建筑轴、细节方块无法混入框架 palette。

机器报告位于 `runs/STYLE-LEARNING-PILOT-v0.1/feasibility_report.json`。这次 PASS 只证明工作流的分层、提取、受约束变化和多视图产物能够执行；它不声称三个框架已经达到美术标准，也不声称任何调试棒状态已通过游戏内更新试验。

本次看图还得到一个有效反馈：第一轮只有外壳时，虽然参数不同，却不能充分表达建筑框架。因此框架定义已经修正，纳入轴网洞口、入口、阳台大线和各面开洞关系，再重新生成七视图。这说明门槛能够暴露并修正流程问题，而不是把一次生成结果自动宣布为成功。

## 四、接下来的实际收敛顺序

1. 给 43 个窗和优先建筑素材做语义裁件，先完成窗、墙缝/檐口、阳台栏杆、屋顶四类。
2. 在目标客户端完成状态手法 A/B，建立“稳定 / 必须禁止更新 / 重载失效”表。
3. 用七视图评分三套框架，保留一个并针对失败面重新抽样，而不是修饰所有候选。
4. 给通过的框架装配少量一级构件，重新看七视图；再逐级增加细节。
5. 生成新的设计编号，不再沿 PAR-001 单一路线递推；PAR-001 保留为旧流程对照。

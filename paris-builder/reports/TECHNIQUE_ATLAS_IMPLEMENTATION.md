# 巴黎建筑手法图谱与库件生成：项目总报告

> 更新日期：2026-10-02（香港时间）。范围：本轮「源作品普查 → 元素拆解 → 跨源研究 → 库件组装首栋」项目。
> 研究证据已由只读审计独立复算。首栋当前修复候选为 `runs/ATLAS-HOUSE-v0.2/`；技术验收及视觉评审必须绑定该候选的最终哈希，第 7 节规定具体门槛。

## 1. 项目目标与当前结果

这轮工作的目标是把真人搭建的巴黎建筑拆成可追溯的建筑手法，再让生成器使用这些真实构件。交付同时包含研究资料、构件库、跨源规律、可执行装配入口和第一栋生成候选。源作品的形态、立面的构图与方块技法各自保留独立职责；技法不再只通过几个程序参数表达。

研究部分已完成实物与证据核对：扫描 123 个源文件，SHA-256 去重后为 80 个独立源；v3 的 25 件与本轮 v4 的 84 件合计 109 件，覆盖 14 个主源中的 11 个。109 件均能逐格追溯到当前源文件和源坐标，清洗差异全部限定在有账目的版本改名。类别对照覆盖 17 类，输出 18 张类别页与 1 张封面。19 件含 Create 模组方块，保留为研究证据；另外 90 件的原版兼容标记与已有注册表校验为 PASS。

生成部分已经有独立的库件装配模块与命令行构建器：`src/paris_builder/atlas_assembly.py`、`tools/build_atlas_house.py`。首栋选择街区1 的成套语汇，沿北面和西面布置两翼与转角塔亭，使用源件决定开间、层位和屋顶剖面。它是当前图谱的一条可执行落地路径；图谱全部形态、全部构件变体与网页整链的自动选择仍需后续接入。

本轮收官范围沿用原任务末尾已经确定的里程碑：④a「库件组装引擎 + 街区1 语汇转角公寓首栋」、④b「首栋渲染验收并修复」、以及项目详尽总报告。早期方案讨论过约 24×30 的切角楼；最终实施选择同源街区1塔亭和两翼、按源相对层位重组。此栋的参数和验收据此核定，不把旧 ATELIER 候选的规格或通过记录转移过来。

## 2. 材料范围与研究方法

### 2.1 80 个独立源的含义

123 是文件数，80 是内容哈希数；43 个重复文件是 `_incoming_schematics/` 中已有源的重复副本。80 个独立源中，36 个是建筑级，44 个是窗或构件级。建筑级范围包含 14 个主要参考源以及修改版、小房子、斜面和转角校准材料。校准材料用于识别一面贴片、其他面缺少处理等局限，不自动升为可装配正例。

43 个窗已经在 v1 进行标注，统一目录实际提供 43 个 `window` 条目；本轮普查的 44 个构件级源还包括修改版窗。**43 窗没有重新计入 109 个 v3/v4 裁件**。两套数字表示不同的证据层，不能相加后宣称有 152 个新拆件。

### 2.2 从源到构件的固定管线

1. 为只读源记录文件路径、SHA-256、DataVersion、尺寸、非空气数量和精确状态指纹。空气按方块名称识别，调色板编号不作为语义。
2. 用源局部坐标的半开区间 `[x0,y0,z0,x1,y1,z1)` 截取完整可读的元素。原范围输出 `source-crop.schem`，裁掉外围全空气后输出 `detail.schem`。
3. 保留门叶半态、楼梯形状、墙/栏/玻璃板连接等源状态。清洗只允许显式目标版本改名；当前逐格改名均为 `minecraft:chain → minecraft:iron_chain`，属性保留。
4. 记录 `clean_origin_source_xyz`、清洗差异、来源哈希、裁件哈希、建筑用途、约束、朝外方向以及状态上下文。
5. 进行文件回读和目标注册表校验，输出 `registry.json`。模组内容保留原证据，同时标记 `compatible_vanilla=false`。
6. 逐件输出七视角与 overview，写入 `role_review`。同类件再汇总到跨源对照卡，提炼共同做法、变体和负发现。

每件目录包含 `record.json`、`source-crop.schem`、`detail.schem`、`registry.json`、`source-nbt-context.json` 和 `previews/`。其中 source NBT 是追溯上下文；裁件导出以方块几何为主，不能把 NBT 文件存在理解为实体或方块实体已被装配导出。

### 2.3 本轮研究审计的做法

审计工具 `runs/ATLAS-HOUSE-v0.1/research-audit/audit_research.py` 只读已有源、库、索引与图片，并将证据写入同目录。它重新读取每个 `.schem`，直接对比源坐标切片和导出状态，验证每一条改名的前值、后值、坐标和完整性；并重新统计裁件尺寸、非空气状态数量、命名空间和文件哈希。

这比读取既有 `validation=true` 多一步：审计结论来自当前文件的逐格比较。PNG 核对证明文件可打开、七视角齐全、对照页尺寸符合 manifest。既有 `role_review` 表示先前 agent 的建筑判读记录；本轮 PNG 可读性检查本身不等同于重新目检 763 张图，更不等同于游戏验收。

## 4. 已沉淀的可复用建筑知识

完整论证见 `reports/TECHNIQUE_ATLAS_STUDY.md`，下表将研究结果转成生成器要做的具体决策。共同规律来自跨源比较；孤例保留为候选分支，不将每个源的做法强行推广。

| 元素 | 可复用结论 | 代表证据 | 生成器使用方式 |
|---|---|---|---|
| 窗 | 门叶薄窗面、玻璃背衬与深内衬形成有纵深的组合；贵族/标准/阁楼有不同尺度 | `st1-window-bay-*`、`s3-window-bay`、`st7-window-screen-oak` | 先选等级与件宽，再推开间；保留冻结 half/facing |
| 转角 | 切角、圆弧、船头、角亭和凹角都是独立构图 | `b7-corner-chamfer-west`、`b2-corner-body-*`、`st4-prow-*`、`st1-corner-turret-*`、`b5-corner-chamfer-*` | 为地块选转角族，并生成过渡、收头、绕角带 |
| 店面 | 橱窗、真入口、招牌、竖梃与披檐成套；入口用空气凹廊表达 | `st5-shopfront-*`、`st6-entry`、`st7-shopfront-warped-corner` | 按模数交替入口/窗面，明确真开口；斜面跟随踏步朝向 |
| 老虎窗 | 双排制度及白/深颊板等级编码；齐平嵌坡也有源证据 | `st1-dormer-*`、`st4-dormer-*`、`b6-dormer-west` | 和屋面坡折位置一起选，禁止孤立浮贴 |
| 烟囱 | 成组、锚在脊/坡顶，并有花盆/铁砧等收头；砖感常由蘑菇块/花岗岩达成 | `st1-chimney-group`、`st4-chimney`、`s3-chimney` | 选组宽、位置和压顶，审计完整保留程度 |
| 檐口/阳台 | 多层叠涩、绊线钩齿饰、横链线脚、拉杆牛腿与连续绕角带 | `st1-cornice`、`b1-cornice`、`st4-balcony-band` | 横向铺设需保持相位，边界做延续或收头 |
| 柱廊 | 冻结墙连接可拼圆柱；柱线和内窗墙构成双层立面 | `b6-colonnade-bay` | 参数应包含柱线/窗墙间距与通行纵深 |
| 屋顶 | 檐沟→陡坡→坡折→缓坡→屋脊是剖面体系；材质肌理、老虎窗、烟囱、脊饰必须协调 | `st1-roof-section`、`st4-roof-section`、`b6-roof-section` | 为屋顶选完整组合，按剖面放置附属件，处理交接与端部 |

冻结状态是手法的一部分。诸如门叶全 lower、墙 `up=false`、楼梯 inner/outer、压力板 powered、栅栏门 open 等，均可能为特定建筑作用而存在。不能因为它们不符合一般功能门或自然邻接更新习惯，就把源件重写为常规状态。

### 4.1 负发现与事实校正

| 发现 | 证据与核对层级 | 对生成的约束 |
|---|---|---|
| 素材5 的所谓「切角」实际为 L 形凹角小庭 | `DECOMPOSE-b5b7.md` 的源坐标探针和三段件；语义为既有目检记录 | 选择凹角族，不能套 45° 平面切角 |
| 素材2 穹顶在西立面中央前突体，不在转角 | `DECOMPOSE-building2-corner.md`、crown 两件 bbox | 圆弧转角与穹顶分开处理 |
| 素材7 筒拱「光眼」是实心浅材图案 | `b7-roof-vault-eye` 独立重读 **0 个 glass 方块**；整楼无老虎窗为既有源扫描/目检结论 | 不把浅色屋面图案当采光天窗 |
| 素材6 内院素墙 | `b6-court-face` 独立重读只有四种实体石材，0 glass；全院四面结论见源探针/报告 | 记录此源差异，不能默认府邸内院也已完成精装 |
| 街区4「斜面」指平面斜向，并非地形坡度 | `DECOMPOSE-street4.md` 的船头及层位测量 | 结构选择楔形/斜立面，地形高差另行建模 |
| 源实芯体与可用装饰壳必须区分 | 素材5白羊毛芯；街区7灰实芯与6层立面壳，见相应报告和裁件 | 裁件范围控制在元素；生成内部空间另作明确决定 |

这里将可直接复算的方块事实和既有建筑判读分开。局部裁件的负发现支持该局部构造，不能单凭一件自动证明整个源不存在其他例外。

### 5.2 从件反推建筑参数

首栋构建器采用街区1 原生北向件，北翼直贴，西翼使用 turns=3。位置和方块状态一起旋转，旋转后导出派生件，以零旋转落位，使几何和回读审计使用同一坐标约定。开间节奏与楼层来自套件本身，填充先写，库件后写。

当前选择保留街区1 的源层序：拱廊/标准窗/下阳台/贵族通高窗/上阳台/檐口窗带/曼萨德。原设计设想的「标准层×2」与这套源件及目标总高不能直接兼得，因此首栋是源层序的变长装配；不能声称任意楼层组合已经完成。

7 个街区1 模组件的使用决策逐项入账：阳台和檐口重裁干净段，转角顶帽与屋顶墙柱另建原版派生件，中央入口/内院/山花因本栋构图不需要而明确排除。每一次替换或排除应能回到 `assembly.json` 和派生说明。

### 5.3 接入边界

本轮已有独立构建入口，可以执行并产出候选。搜索当前代码调用点显示，首栋的选择策略主要位于 `build_atlas_house.py`；尚未形成覆盖五类形态的通用选择器，也未证明学习网页、模型阶段链和城市层都调用此套装配策略。完成首栋后应把稳定接口接到既有单栋装配层，避免再复制一套几何或选择逻辑。

### 5.4 源件和派生件的实际约束

`atlas_assembly.Assembler` 当前在装配入口校验来源，而不是只信任条目的兼容标记。原件须是带源证据的v4条目；构件文件哈希必须等于record，当前主源哈希也必须等于record。按`clean_origin_source_xyz`重新取源切片后，只有有账目的`chain → iron_chain`改名被允许，其余状态逐格相等。源件变化或源文件变化会直接拒绝装配。

派生件须明确给出`source_id`和操作序列。当前允许的位置与状态同转、半开区间子裁，以及`create:cut_calcite_wall → minecraft:diorite_wall`显式白墙替换；墙连接属性保留。注册时将操作重放到原件，逐格比较请求输出，保存源证据和输出哈希，再跑独立原版注册表。后续落位时还会重验派生文件哈希和原件来源链。门叶的`half`冻结态保留，装配过程不能凭一般门的常识自动配对。

每次落位记录唯一owner、件id、角色、锚点、裁齐范围、同状态重叠、异状态覆盖数量、前owner与坐标样本。相同件重复落位也有独立身份，便于区分横铺重复件和两翼交接。场景越界与明确的共墙裁齐分开计数；最后从导出schem回读检查。这些约束支持可追溯装配，并不单独证明每一个落位在建筑品质上合理，最终仍要进行几何量测与目检。

### 5.5 从v0.1失败账目到v0.2修复

旧构建最后写共墙防火墙，曾擦除已经放置的库件；烟囱组采用整件带坡脚装配再以边界裁齐，部分后写老虎窗和共墙又接管烟囱附近状态；横铺的末件还可能为追齐长度而整件退回覆盖相邻件。v0.2把结构与共墙放在库件之前，横铺尾段登记为有来源的子裁，再让标准窗在拱廊之后、檐口在上阳台之后落位。每次写入都仍有独立账目，不通过移除诊断来得到通过。

烟囱采用`st1-chimney-group`的完整前侧子范围`[0,0,0,8,10,10)`及其西向旋转件，保留烟囱轴身与收头，排除会延伸到共墙外的后侧坡脚。此处「完整」指该前侧烟囱与顶端结构，不是宣称原8×10×18整裁件所有内容都在最终楼内。

交接规则按具体来源角色、目标角色、实际件相交盒和建筑层位限制，涵盖两翼屋面、同源带状件、塔亭端柱、老虎窗穿坡及烟囱坡脚。老虎窗接管烟囱的许可范围只到坡脚，不包含烟囱轴身。无解释损失、整件丢失、场景出界和异常角色覆盖仍须拒绝；有限规则本身也不能替代最后的烟囱完整度、街面开口与屋面接缝检查。

## 6. 旧原型屋顶污染件的修复证据

「屋顶污染」的具体对象是 `v3:s3-roof-section`：原裁件是完整源坐标证据，但范围带有裁断天窗内容（iron_door/white_stained_glass/lever/diorite_wall）和烟囱杆。横向重复整个裁件，会把这些非重复屋面内容一起铺到坡面和屋脊。

`tools/build_part_prototype.py` 已存在两部分修复实现：主体段按明确黑名单过滤天窗残件，并将烟囱杆削至邻列屋面线；街面坡则使用母本 `street3-facade-3` 的局部列 1、2、3、20、y36–42、z0–7，拼成四格宽的干净派生条，再横铺。派生件为 `runs/PART-PROTO-v0.1/derived/roof-section-clean.schem`。

本轮研究审计对这个派生件逐格复算，检查它是否确实等于上述四列，并保存派生哈希和旧原型 assembly 的快照。**这只能确认前坡派生件的来源和状态，完整旧原型屋顶的过滤、收口、最终视觉需要另行验证。** 原型旧报告还记录了端部缺少女儿墙柱、削平处灰色贴面以及旧式 stamp 总账不全匹配的局限。

这项旧原型修复与首栋街区1 的 `front-vanilla` 屋面派生是两个不同对象。前者处理重复裁件夹带内容，后者处理模组墙替换与前坡范围；不能用首栋成功替代旧原型修复证据，也不能为了装配方便改写源库件后继续宣称源状态未变。
